# Changelog

All notable changes to Die Kollektion Werkstatt. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- **A Blender add-on for fitting accessories.** It opens any vehicle as its parts, attach points, donor references and upgrade nodes; you show a slot, pick an item, nudge it in steps of 1 mm, 1 cm or 10 cm, or turn it in steps of 0.1° to 5°, each times 1 to 50, duplicate it, and save the vehicle's `placements.json` with one line per entry. Parts, attach points and upgrade nodes sit where the plugin puts them at spawn: the wheelbase sweep (the rear axle and springs go back with it), the track and the definition's transforms. It works in whatever checkout and branch you point it at, shows the branch, and only writes the file: a save keeps the file's entries for nodes the scene doesn't show and refuses a file changed on disk since it was read. Each change is one undo step. The list marks the options the game never shows (the roll cage, and the bumper winch on stock cars) and those our trucks show with a tool. Every panel action is also an operator and a call in `werkstatt_addon.api` returning plain dicts, so an agent can drive it over the Blender MCP server, measure an item against the body, wheels and other fitted items (`clearance`: the gap, or how far and which way it must move to clear, inside or crossing) and render the same four review views of it after each nudge. "Build and check" runs `make loop` in the background with its output streaming into a text and a Cancel button, so Blender stays usable while it builds. `make blender-addon` zips it; docs/blender_addon.md has the how-to.
- **Placements for upgrade parts.** A vehicle's `placements.json` moves, turns or scales any upgrade node (a winch, a roof rack, a whole slot such as the roof) on that vehicle only, and can add copies of an item, such as a second keg pile in a bed, shown whenever the item is fitted. The plugin applies it to the spawned truck and to the mechanic's preview. `make extract` now also exports each donor's upgrade nodes and their meshes (`extracted/<donor>/upgrades.json`), and `make check` tests the plugin's reader against the same fixtures as the Blender add-on's model.
- **The bumper winch shows while a truck carries the portable winch.** The game never shows the winch node on a bumper; our four trucks now show it while the portable winch is in their tool loadout, on the truck you drive and on the mechanic's display, where it appears or goes the moment you add or remove the tool in the Tools screen. A vehicle manifest names such nodes in a `toolNodes` block (node path to the tool's ItemId); the stock Mammoth is unchanged. No new item and no save change.

### Changed
- **Game updates are handled inside the game.** `make deploy` now installs Die Kollektion's loader in `BepInEx/plugins/` and the plugin in `BepInEx/VehicleMods/`. The loader can't be broken by a game update; when the game has updated it rebuilds the plugin for the new version before loading it (a few seconds, with a small progress window), then starts it as usual, and the main menu says `rebuilt for build N`. If it can't (no .NET SDK, or the plugin's sources changed), it says how to fix it and, when your save holds our trucks, closes the game instead of letting it hang at load. The launch option is plain `"./run_bepinex.sh" %command%` again (`run_werkstatt.sh` keeps working), and nothing runs after you quit. Run `make deploy` once to switch an existing install over.

### Fixed
- **No silent stock session with trucks in a save.** On the first start after a game update, BepInEx rebuilds its interop inside the game, and that can leave the plugin no safe place for its hooks; it then ran without the mod while the save held our trucks. With trucks in any save the game now closes at once with a dialog saying starting again usually fixes it (it does: the next start has room); without trucks it runs stock and says so. The memory map of such a session is saved to `BepInEx/dobby-maps.txt` for a report. The loader's progress window now stays up at least 1.5 s, so a fast rebuild shows it.
- **Our trucks get the cosmetics already unlocked.** A reward that unlocks a cosmetic gives it to every car in the catalogue at that moment, so the trucks missed everything unlocked before they were registered (44 cosmetics on a played save). `make save-add` now gives each truck a state on every cosmetic its donor owns, and catches up when run again (needed only for cosmetics unlocked while the plugin wasn't loaded, or granted on load before the trucks register); performance upgrades, which are bought per car, are never copied. The save is written as the game writes it, one compact line; each backup gets a name of its own, is checked against the save before the save is replaced, and the one taken before the trucks were first added is never pruned.

### Added
- **A test save for trying every part on every truck.** `make save-test` (game closed) swaps in a copy of your save in which every car, our trucks included, owns every cosmetic, upgrade and livery it offers, so the mechanic previews each one on the truck. Your own Saves folder (save, fog of war, animal photos) is parked untouched until `make save-real` renames it back; `make save-add` also stops pruning backups that aren't its own.
- **Releases reach Nexus Mods on their own.** When a GitHub release (not a prerelease) is out and its checks pass, CI uploads `die-kollektion-werkstatt-<version>.zip` to the Nexus page as a new version of the main file (the previous one is archived), with that version's entry from `docs/nexus/changelog.txt` as the mod's changelog. It uses Nexus Mods' official upload action and the `NEXUSMODS_API_KEY` repository secret, skips a version Nexus already has, refuses one older than the newest there, and can be re-run for a tag by hand.

## [0.6.0] - 2026-10-19

Halogen headlights on the trucks, a status line on the main menu, and launches that survive game updates.

### Added
- **A status line on the main menu.** The game's build label ends with `Die Kollektion <version> | 4 vehicles, 2 patches registered` when the mod loaded and everything registered; the line turns amber, says what's short and points at `BepInEx/LogOutput.log` when a vehicle, patch or game hook failed, a truck kept its donor's name or icon, or no vehicles were found. No line means the game is running stock. It sits at the bottom of the main menu; if a working install shows no line, the log's `Main menu:` line reports whether the label was active.
- **Update-safe launches.** The Steam launch option is now `"./run_werkstatt.sh" %command%`: Werkstatt's launch script starts BepInEx as before, and when the game has updated since the last deploy it starts the game once without the plugin (a plugin built for the old version hung the game at start), then, after you quit, rebuilds the plugin for the new version in a separate process and installs it again. What it did is in `BepInEx/werkstatt-launch.log`. `make update` does the same by hand; `make status` and `make start` say whether the plugin fits the game's version. Each deploy records that version in `deployed.json`. On an existing install, run `make deploy` first (it installs the script), then change the launch option.
- **Halogen headlights on the four trucks.** A vehicle manifest can carry a `headlights` block: `kelvin`, the headlight colour temperature to aim for, and `intensity`, a factor on the game's. At spawn the plugin gives that vehicle its own copies of the game's headlight and bounce-light configs, so stock cars keep theirs. Both colours move by the step from the game's headlight (about 4200 K) to the target, so the glow on the ground stays as much whiter than the beam as the game made it. The trucks aim for 3200 K at 0.8 of the game's intensity: warmer and a little dimmer. The lens glow is unchanged.

## [0.5.0] - 2026-10-19

The first public release, on GitHub and Nexus Mods. Werkstatt builds the trucks on your machine from your own copy of the game; nothing from the game ships. Native Linux today; Windows support is planned.

### Added
- **The Werkstatt make flow.** `make start` checks the setup and prints one plain next step at a time, from a fresh game install to a deployed mod; `make doctor` lists every check with the install command for your distro; `make bepinex` installs the pinned BepInEx 6 IL2CPP build (be.789, checksum-verified, asks before downloading) and fixes its start script and config; `make all` extracts, builds, checks and deploys; `make undeploy` removes exactly what was installed; `make status` compares repo, build and game folder; `make save-add` puts the trucks in a save after backing it up.
- **Contact sheets.** Each vehicle folder's page on GitHub shows four isometric renders, a rig view of its colliders, wheel colliders and attach points, and the mesh checks (gaps, slivers, culled faces, triangle counts, attach-point checks). `make loop V=<vehicle>` rebuilds one vehicle and summarises what changed.
- **Vehicle folders.** One self-contained folder per vehicle under `vehicles/`, with its manifest (`vehicle.json`, whose `kind` is `novel`, `based` or `patch`), its own meshes, Blender masters and icon.
- **Packs.** `packs/die-kollektion/manifest.json` (strict JSON in the pattern of the game's official livery manifest) and `make pack`, which zips only our own files and refuses anything extracted from the game.
- **The golf-bag canary.** A low-poly golf bag strapped to the roof of The Ding, the first patch on a stock car other than the Mammoth.
- **Review on GitHub.** A Drive report issue form, and pull requests that carry each vehicle's updated contact sheets; `CONTRIBUTING.md` describes the flow.
- `AGENTS.md`, guidance for AI agents helping a person build or tweak vehicles.
- **Releases with the plugin ready-made.** `make release VERSION=x.y.z` (maintainers; `DRY_RUN=1` to rehearse) checks versions and gates, compiles the plugin against the installed game, and publishes `die-kollektion-werkstatt-<version>.zip` (Werkstatt with `prebuilt/`), the pack zip and `SHA256SUMS` on GitHub Releases. With a prebuilt plugin built for the player's game version, `make deploy` installs it instead of compiling, so players need no .NET SDK.
- **CI.** GitHub Actions run every check that needs no game files on each pull request and push (`tools/release.py ci`), and verify each release's tag, versions and assets.

### Fixed
- Rear-section upgrades (tailgate spare, bike rack) sat 18.7 cm inside the bed on the Glyptodon, Megaloceros and Mastodon; they now move with the bed's rear end.
- After the game update of 2026-10-19 the plugin crashed during the logo: the hooks' jump slots could land in memory .NET later overwrites. The plugin now reserves its own block for them as soon as it loads, re-checks it before installing the hooks, and runs the game without the mod rather than crash when no safe block exists. `make check` tests the placement against captured memory layouts.
- The BepInEx download failed with HTTP 403 (the build server refuses Python's default user agent).
